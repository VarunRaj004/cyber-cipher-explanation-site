The problem

A COMPLAINT SHOULD NOT REQUIRE SURRENDERING YOUR IDENTITY.

Traditional complaint channels often place identity, evidence, investigation, and final authority in one system. That makes retaliation, silent suppression, and unverifiable outcomes difficult to rule out. eVoice divides those powers.

Chapter 01

PROVE ELIGIBILITY—THEN BREAK THE IDENTITY LINK.

The Identity Authority checks the person once. It confirms membership and issues a one-use entitlement through an RSA blind-signature flow.

Because the serial is blinded during signing, the authority cannot later match the presented entitlement to the issuance event. The entitlement proves permission, not identity.

What crosses the boundary?A valid, unlinkable entitlement—not the NIC, account ID, or membership-tree position.
Entitlement profile RSA–3072 RSABSSA-SHA384-PSS-Randomized
  • 128-bit random serial
  • One successful submission
  • Valid only for the matter window

ELIGIBLE+ONE USE+ENCRYPTED≠IDENTIFIED

A 60-second signed proof-session lease and a 128-bit challenge ID bind the proof to the active session. The membership circuit uses Groth16 over BN254 with Poseidon and accepts the current root only.

Chapter 03

PRIVATE INVESTIGATION. CONTROLLED PUBLICATION.

Admin side

THE ASSIGNED HANDLER

Only assigned, WebAuthn-authenticated staff unwrap the case key, decrypt evidence, investigate, and record a signed finding.

  • Full encrypted case context
  • Substantiated / unsubstantiated decision
  • No community vote manipulation
TRUST
BOUNDARY
Public side

THE REDACTED DERIVATIVE

Publication approval creates a sanitized statement. The community never receives private evidence, complainant data, or the handler outcome before voting.

  • Approved redacted statement only
  • Anonymous complaint-scoped vote
  • Public aggregate, not private case

Read the fine print

WHAT THIS MVP PROVES—AND WHAT IT DOESN'T.

IT DOES

  • Demonstrate separated role portals
  • Enforce command allow-lists per portal
  • Run the complaint-to-audit journey
  • Package protocol artifacts and tests
  • Show tenant-fixed SaaS boundaries

IT DOESN'T YET

  • Replace an independent security audit
  • Provide production HSM or secret management
  • Claim coercion resistance or endpoint safety
  • Persist the browser demonstration workflow
  • Make community voting legally dispositive
